# 总计划（Program Plan）

依据：`references/gpt-architecture-guidance.txt`（引导）+ 2026-11-19 四项目实测现状。
引导文档原建议"现在只启动 P1"；用户已在另一会话裁决**四项目同时启动**（CHG-0001），但边界保持为"**只做 MVP/骨架，深度建设让位于 Engine**"。本计划继承该裁决。

## 优先级铁律

1. **Engine（项目01）生产链验收是最高优先级**；其他项目的深度建设不得挤占它。
2. 知识质量优先于内容数量；完整工作流优先于批量生成；不批量生成 19 课制造进度。
3. 人工关卡（G1/G2/G3、commit/push、远程创建、部署、断言升级、课程路线、设计方向）不可由 AI 自批；未回复不视为同意。
4. 项目间只通过**文件接口 + 适配器**连接，不建中央服务器，不做强耦合依赖。

## 阶段与门禁

### 阶段 A · 收口与人工审核（当前，阻塞中）
- A1 审计 Render_Notes 未提交批次（D15 + CHG-0001 两来源），按来源拆分提交方案 → **PD-Q1 授权后** commit/push。
- A2 G1/G2 裁决：B4 / B10 / V13–V20 升级 / B11 / B12 / B15 → 记录入 Render_Notes DECISIONS.md。
- A3 P2 试点方向确认（PILOT-L13-plan.md 方案 A/B）。
- A4 P03/P04 本地 git init + 首笔提交（**PD-Q2**）。
- **门禁**：A 完成前不启动任何深度建设。

### 阶段 B · Engine 生产化（P8/P9/P10，最高优先级主线）
- P8：KCR 生产化（reviews/KNOWLEDGE_CHANGE_REVIEW.md 设计 → schema + 工具集成）；文档注册表一致性门禁接入 validate。
- P9：轻量编排（任务合同/依赖/断点恢复/人工暂停；用现有 Python tools + JSON，不上分布式框架）。
- P10：**一批全新资料端到端验收**（引导文档 10 条验收标准：导入→查重→研究→证据→建模→路线→教材→实践→审核→网站→状态留痕）。
- **门禁**：P10 通过 = Engine 核心里程碑达成（不是"19 课写完"）。

### 阶段 C · 学习体验（P2 实施，依赖 A3 + 试点资源）
- 试点页（L13 教材 + 一个交互实验）→ 真实浏览器截图 → 用户确认 → 设计体系推广。
- 不重写网站引擎；web/ 仍是权威离线站；保留全部现有功能。

### 阶段 D · Governance Kit 验证与接入（P3 深化）
- D1 双案例迁移验证：Render_Notes（适配现有 .agent/DECISIONS/reviews/KCR）+ 一个全新普通项目（证明不依赖知识结构）。
- D2 验证通过 → 远程创建（**PD-Q3**）→ 发布。
- D3 Render_Notes 反向接入方式经 **ADR 裁决**（替换/共存）；过渡期 Render_Notes `.agent/` 保持唯一权威，不产生第二事实源。
- 吸收 `E:\AI-Tools\doc-governance` H1–H7 规则注明出处；不改 skills 原仓。

### 阶段 E · Radar 常态化（P4 深化）
- E1 PAT 授权（**PD-Q4**，环境变量注入）→ 真实采集 → 每日快照积累。
- E2 快照 ≥7 天后出首份周报（历史不足如实标注，禁止伪造 7/30 天增长）。
- E3 首个候选经人工批准 → 标准 JSON 导出给 Engine Research Agent（不自动导入）。

- 不把治理做进 skills 仓；不让 learning-experience-design 独立成仓。
