## 4. 已知限制与本轮发现（请你在 G3 裁决时权衡）

**① 课时页不链接课文正文本身（首轮实测发现；已按你 2026-11-27 的批准修复，待你确认修复方式）**

原状：教材模式的课时页包含学习目标、前置课、术语、自检和测验，但"按顺序阅读"指向的是**课源提取文档**（`08-具身智能/…`），不是写好的课文（`courses/embodied-loop-journey/lessons/…`），指向课文正文的链接数为 0。这是既有设计，主课程相同。

修复：在课时页"前置检查"之后、"按顺序阅读"之前加入"课文正文"区块，链接到本课的课文全文（文档路由）。实现上按"课程目录 + 课时编号前缀"在站点包的文档表里定位课文，因此**三条课程路径都被覆盖**（具身 6/6、Pilot 5/5、主课程 19/20；主课程只有 L00 地图课没有正文，不显示该区块）。样式沿用现有阅读清单，没有新增 CSS。

验证：§3.3 的真实点击链路；回归测试 `test_lesson_page_links_to_lesson_body`（publish 回归 34→35）。改动不涉及 24 个冻结产物，也不改变站点包内容。

**修复方式是否认可、是否据此通过 G3，仍由你决定。** 入口的视觉效果没有做人眼验收。

**② 无绑定交互实验**：六课练习都是纸面题（验收包 §8 第 2 项，G2 已据此扣分）。

**③ 证据核验的深度**：Tobin 2017 与 DAgger 2011 只核对了官方摘要，没有重开全文；MuJoCo 官方文档取自 main 分支的活文档，没有对应发布版本号。

**④ 浏览器验收的边界**：只测了本机 Edge 无头模式；没有覆盖其他浏览器或真机；公式以渲染元素计数确认，**没有做人眼视觉验收**；测验只验证了交互行为，没有逐题核对答案对错（答案正确性来自独立审读与 G2）。

**⑤ 独立 CI**：仓库没有 `.github/workflows/`，以上都是本机实跑记录，不是远端独立复现。

## 5. 执行口径（统一两份文档的命令顺序）

两份文档给出的顺序不同：`reviews/approvals/README.md` 是"先登记记录，再通过关卡"；验收包 §7 第 7 步是"先通过关卡，再登记记录"。

**这不是功能冲突。** 实测工具代码：两种顺序都能走通，唯一的硬约束是 `record` 与 `gate --pass` 的审批人字符串必须完全一致。但为了留下干净的证据，**统一采用"先登记、后通过"**（登记时工作树干净、提交号明确）；验收包 §7 第 7 步以本节为准。

以下是**你本人决定批准 G3 之后**才执行的命令，现在不要运行。把 `<你的审批署名>` 换成同一个字符串：

```powershell
# ① 登记 G3 审批记录（冻结 24 个 run 产物 + 本批补充材料的哈希）
py -3 tools/approval_chain.py record --run-id RUN-2026-11-23-embodied-batch1 --gate G3 --approver "<你的审批署名>" --scope "G3：具身六课 E01–E06 发布就绪验收" --path reviews/embodied-batch1/G3-readiness-addendum.md --path reviews/embodied-batch1/browser-qa-g3-20261127.json --path reviews/embodied-batch1/KCR-RETROSPECTIVE-REVIEW.md

# ② 通过关卡（审批人必须与 ① 完全一致）
py -3 tools/run_state.py gate --run-id RUN-2026-11-23-embodied-batch1 --pass --approver "<你的审批署名>"

# ③ 复核
py -3 tools/approval_chain.py verify --run-id RUN-2026-11-23-embodied-batch1 --gate G3
```

说明：
- 本批补充材料**没有登记为 run 产物**（否则会使 G1/G2 两条记录的复核报"批准后新增产物"）。它们通过 `--path` 纳入 G3 记录的范围。执行前请确认这些文件自本提交起没有再改动。
- 正文入口修复改的是 `web/assets/app.js` 与回归测试，二者都不是 run 产物，也不在上面的 `--path` 列表里；它们随各自的提交留痕。
- **身份认证仍未进行**：审批人只是一个字符串。你自己在本机执行命令，是目前唯一能证明"批准者是你"的方式。如果你选择授权代理代为执行，记录里会如实写"代理代录、未经身份认证"。
- KCR 不在这组命令里。`run_state.py kcr --to APPROVED` 只是状态转换，必须在 `KCR-2026-11-002` 逐项裁决之后才能执行，见 `KCR-RETROSPECTIVE-REVIEW.md`。
