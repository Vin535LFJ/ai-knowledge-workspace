# 开源生态与实践路径

> **本章回答**：十六周路线的第一个交付物为什么是"可复现"？
> **写作纪律**：正文重组课源的关键内容，权威表述链接课源锚点；可复现性分层中 GPU 一行经 MJWarp 官方 FAQ 逐字核验，CPU 一行经 MuJoCo 官方文档 Reproducibility 节逐字核验（2026-11-25）；生态项目的名称与定位是 2026-11-12 / 11-14 / 11-17 的源快照，引用须带快照日期，具体版本与许可以官方页面为准；本课断言写作时均为 open/low。
> **路线位置**：embodied-loop-journey 第 6 课·收官（E01 → E02 → E03 → E04 → E05 → **E06**），建议 40 分钟；无绑定交互实验，练习为纸面规划与判断。
> **学习目标**（完成本章后你应能）：① 说出具身开源生态的四组与起步三件 ② 解释可复现性分层（CPU MuJoCo / GPU MJWarp） ③ 识别具身学习实践的九条常见坑——前置概念见 [E05 模仿学习复合误差与 Sim2Real](E05-模仿学习复合误差与Sim2Real.md)。

## 1. 从一个问题开始

前五课给出了判据、时间账、对齐、运动学和误差。一个自然的冲动是：马上找最强的模型、最大的数据集，把东西跑起来。

课源给了一条相反的路线：十六周里的**第一个交付物不是模型，是"可复现"**——代码能从一个干净环境按 README 重跑出同样的结果（[课源 §2](../../../08-具身智能/06-开源生态与实践路径.md#2-十六周路线第一个交付物是可复现不是模型)，断言 `V86`）。

为什么把这么朴素的东西排在最前面？因为在具身场景里，**一个不能复现的"成功"，无法证明它是能力而不是运气**——课源给的第 4 周验收标准正是"有可重复的成功率，而不只展示一段成功视频"。E05 算过，单步 95% 的策略在 50 步上只有 7.7% 的整链成功率——一段成功视频什么也说明不了。

## 2. 学习前提

- **E05**：成功率必须带试验次数报告；域随机化买的是覆盖。
- 本课不需要新的数学。

三个首次出现的术语，先给一句话解释：

- **ROS 2**：机器人软件的通信与接口标准（本身不是具身大模型）。
- **可复现性**：别人从干净环境按你的说明重跑，能得到相同的结果——能逐位相同时比逐位，不能时比多次运行的统计分布。
- **许可红线**：代码、权重、数据集、仿真资产可能各自用不同的许可，能下载不代表能商用。

## 3. 直观认识

把生态四组想成**一间厨房**：

- **A 基础设施**是水电煤和灶台——没有它什么都做不了，但它自己不做菜；
- **B 仿真环境**是练习用的 mock 灶台——可以随便试错，炸了不心疼；
- **C 模型与训练框架**是菜谱和厨师训练课程；
- **D 数据集**是食材库。

> **类比的边界**：厨房类比帮记住"四组各管一段"，但它给不出**起步三件为什么是这三件**——选择依据是"桌面操控主线最少需要几件"，属于工程判断，不是类比能推出来的；也概括不了许可红线（食材能拿到 ≠ 可以开店卖）。类比到"分组"为止，选型与许可见 §4.1。

## 4. 一步一步理解原理

### 4.1 生态四组与起步三件

具身开源生态分四组（[课源 §1](../../../08-具身智能/06-开源生态与实践路径.md#1-生态四组与起步三件)，断言 `V82`，**源快照 2026-11-12 / 11-14 / 11-17**）：

| 组 | 职责 | 代表项目 |
|---|---|---|
| A 软件基础设施 | ROS 2 管通信与接口；MoveIt 2 管机械臂（逆运动学 / 碰撞 / 轨迹）；Nav2 管移动底盘（导航 / 避障） | ROS 2、MoveIt 2、Nav2 |
| B 仿真环境 | MuJoCo 偏通用物理与控制研究；Isaac Lab 偏 GPU 大规模训练；ManiSkill 偏操控任务与基准 | MuJoCo、Isaac Lab、ManiSkill |
| C 模型与训练框架 | 策略与 VLA 模型的训练框架 | LeRobot、OpenVLA、openpi、Octo、GR00T |
| D 数据集 | 跨平台汇总、真实操作、低成本示范采集 | Open X-Embodiment、DROID、ALOHA |

**起步三件（桌面操控主线）：ROS 2 + MuJoCo + LeRobot**——通信、物理、学习各一件。三个仿真环境定位有交集，**不需要一开始全装**；ManiSkill、Isaac Lab 等到第 3–4 周再按任务加入。

**许可红线**：代码、权重、数据集、仿真资产可能用不同许可，**能下载不代表能商用**，逐项核对。

### 4.2 十六周路线：第一个交付物是可复现

每周 8–12 小时 × 16 周 = **128–192 小时**；至少一半时间动手（[课源 §2](../../../08-具身智能/06-开源生态与实践路径.md#2-十六周路线第一个交付物是可复现不是模型)）。关键周的验收标准：

| 周 | 验收 |
|---|---|
| 0 | 代码能从干净环境按 README 重跑 |
| 4 | 有可重复的成功率，而不只展示一段成功视频 |
| 5 | 验证集与测试集分开，能报告失败案例 |
| 10 | 不把"模型能加载"当"机器人能执行"，给出定量评估 |
| 13 | 多次运行统计成功率，失败后重新观测而不是盲目重放 |
| 15–16 | 第三方能按报告复现主要结果 |

评测有两条硬要求：成功判定写成**可执行规则**；报告**试验次数与初始条件分布**——"同一初始条件重复 100 次不构成 100 个独立样本"。这两条与 E05 §4.4 完全对应：没有 n 的成功率无法解读。

注意第 13 周那一条——"失败后重新观测而不是盲目重放"——正是 E01 闭环判别三问的第①②问。

### 4.3 可复现性分层：先问设备，再问物理后端

"仿真可复现"这句话必须问一句：**在哪种设备上、用哪个物理后端？**（[课源 §3](../../../08-具身智能/06-开源生态与实践路径.md#3-可复现性分层官方文档核验)，断言 `V83`；GPU 一行经 MJWarp 官方 FAQ 逐字核验，CPU 一行经 MuJoCo 官方文档 Reproducibility 节逐字核验）

| 运行方式 | 可复现性（依据） | 含义 |
|---|---|---|
| CPU 上的 MuJoCo | **逐位可复现**，附三个警告（MuJoCo 官方文档 Reproducibility 节，2026-11-25 核对原文） | 同版本、同架构下可以逐位重跑 |
| GPU 上的 MJWarp | 官方 FAQ："Is MJWarp on GPU deterministic? **No.**" | 默认非确定；要确定性须切回 CPU（`wp.set_device('cpu')`） |

CPU 可复现的三个警告：保存全部积分状态（否则 warmstart 不同）；接触事件对初值高度敏感（混沌放大）；结论只在同版本、同架构内成立。MJWarp 在 GPU 上非确定的原因是 GPU 上原子操作的顺序不固定。此外两者精度不同（MJWarp float32、MuJoCo float64），求解器设置、碰撞、小摩擦值对浮点表示敏感。

> **证据的边界**：官方 FAQ 说的是 MJWarp 这一个后端。别的 GPU 物理后端是否确定，取决于各自的实现与文档，本课没有逐一核验，所以不能替它们下结论。

**实际后果**：在 MJWarp 上两次仿真跑出不同的结果，不是 bug，是默认行为。做对比实验时，要么切回 CPU，要么用多次运行的统计分布来比——而不是比单次结果。

### 4.4 九条坑与一条铁律

课源把九条坑排成一列（[课源 §5](../../../08-具身智能/06-开源生态与实践路径.md#5-九条坑源逐字要点)，断言 `V87`）。一行读完记不住，这里按"用什么能识别它"分成三组：

- **前几课的尺子直接能查出来的**：只看演示视频、把仿真成功当真实成功、忽略推理延迟、忽略动作空间。
- **属于做法问题的**：把语言理解当行动能力、一次引入太多组件、盲目升级依赖。
- **属于数据与合规问题的**：数据泄漏、混淆开放与可商用。

第一组四条，逐条对应前几课：只看演示视频违反 E01 的判别第①问（物理结果没有被重新观测）；把仿真成功当真实成功违反 E05 的 Sim2Real 七来源；忽略推理延迟违反 E02 的时间预算账；忽略动作空间则撞上下面的动作接口铁律——E04 算过，关节角到末端位姿是唯一对应的，反过来不唯一，而且是否奇异只看关节角（θ2 是不是 0° 或 180°），换句话说，"用哪种量当动作"不是记法问题，换了动作表示，同一组数字的含义就变了。

动作接口铁律：关节位置、关节速度、末端位姿、夹爪开合、动作词元**互不兼容**，换接口后权重未必能用。

## 5. 反例与易错点

| 易错做法 | 问题在哪 | 正确做法 |
|---|---|---|
| 第一周就找最大的模型和数据集 | 无法证明成功不是运气 | 第 0 周先让代码从干净环境可重跑 |
| 一开始把所有仿真器都装上 | 组件多、排障难 | 起步三件，其余按需加入 |
| 认为"仿真可复现"不分设备与后端 | MJWarp 在 GPU 上默认非确定 | 要确定性切回 CPU，或用统计分布比较；其他后端查各自文档 |
| 能下载就认为能商用 | 四类资产许可各不相同 | 逐项核对许可 |
| 两次 MJWarp 运行结果不同就当 bug | 这是默认行为 | 多次运行统计，或 CPU 对照 |
| 同一初始条件重复 100 次当 100 个样本 | 样本不独立 | 报告初始条件分布 |

## 6. 动手练习

每题给出"做什么 → 预期 → 机制"。

**练习 1 · 规划起步组合**
你要做桌面抓取的学习实验，第一周应该装哪三件？什么时候考虑加 GPU 大规模训练的仿真器？
预期：ROS 2 + MuJoCo + LeRobot；GPU 大规模训练仿真器到第 3–4 周按任务加入。
机制：起步三件覆盖通信、物理、学习各一件，先降低排障复杂度。

**练习 2 · 算时间投入**
每周 10 小时，坚持 16 周，总投入是多少小时？其中"至少一半时间动手"意味着多少小时？
预期：10 × 16 = **160 小时**；动手至少 **80 小时**。
机制：路线按 8–12 小时 / 周设计，总量 128–192 小时。

**练习 3 · 判断可复现性**
你在 MJWarp（GPU）里跑同一策略两次，成功率一次 61%、一次 58%。这能说明策略变了吗？
预期：不能。MJWarp 在 GPU 上默认非确定，单次结果不能直接比较；应切回 CPU 对照，或多次运行后比较分布。
机制：GPU 上原子操作顺序不固定，导致 MJWarp 默认非确定。

**练习 4 · 许可判断**
某数据集可以公开下载，某模型权重也可以公开下载。你的产品可以直接商用吗？
预期：不一定。数据集、权重、代码、仿真资产的许可各不相同，须逐项核对。
机制：能下载 ≠ 可商用。

## 7. 自测

合上正文，回答下面三题（与课后练习一致）：

1. 一个项目只放了演示视频就说成功，用前几课的哪把尺子能识别它？该拿什么来代替演示视频？
2. 第一个交付物为什么是可复现而不是模型？
3. MJWarp 在 GPU 上为什么默认不可复现？其他 GPU 后端能直接类推吗？

参考答案：第 1 题——E01 的判别第①问（物理结果有没有被重新观测），见 §4.4 第一组；代替演示视频的是可重复的成功率，带试验次数与初始条件分布（§4.2 第 4 周验收标准，E05 的统计口径）。第 2 题——见 §1 与 §4.2 第 0 周验收标准。第 3 题——见 §4.3 与其后"证据的边界"。起步三件由练习 1 覆盖；生态四组没有练习或自测题覆盖。

## 8. 这一课的边界与承上启下

- **本课断言 `V82`、`V83`、`V86`、`V87` 均为 open/low**：V82 的生态信息为 2026-11-12 / 11-14 / 11-17 的源快照，单源；V83 的可复现性分层中 GPU 一行有 MJWarp 官方 FAQ 支持、CPU 一行有 MuJoCo 官方文档 Reproducibility 节支持（GPU 一行 2026-11-24 取文、2026-11-25 复核，CPU 一行 2026-11-25 取文），但官方声明会随版本变化，引用须带取文日期与"同版本、同架构"条件；V86 的逐周验收表为源文要点，其中"不能复现的成功无法证明是能力而不是运气"是与第 4 周验收标准一致的教学解释，不是源文原句；V87 的九条坑与动作接口铁律是源库的工程经验清单，单源。升级待人工裁决（G1 队列 `reviews/embodied-batch1/G1-verification-queue.md`）。
- 本课没有给出任何项目的版本号、性能数字或显存需求——这类信息变动快，未经核验不进教材。
- 与主课程的连接：可复现性与 [L15 性能评测与项目复盘](../../video-rendering-journey/lessons/L15-性能评测与项目复盘.md) 是同一条纪律的两面。

**路线收官**。六课连起来是一条线：**先确认闭环真的闭合（E01），再算清每一轮花多少时间（E02），把时间误差变成毫米（E03），确认机械上到得了（E04），算清学出来的策略在长链上还剩多少成功率（E05），最后让这一切可以被别人复现（E06）。**

本课程是首批六课的"可手算最小核"，不含交互实验；空间 6R / 7R 逆解、动力学、碰撞检测、真机部署流程均未覆盖。回到主课程：[一帧画面的探索之旅](../../video-rendering-journey/lessons/L01-为什么视频不是-RGB.md)。
