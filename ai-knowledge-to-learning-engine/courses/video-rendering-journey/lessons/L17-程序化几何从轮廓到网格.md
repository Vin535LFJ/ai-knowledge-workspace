# 程序化几何 · 从轮廓到网格

> **本章回答**：不导入模型文件，怎样用一条公式生成一张网格？
> **写作纪律**：正文用自己的语言展开推导，权威定义与完整细节链接主文档锚点；陌生术语首次出现给出一句话解释。
> **路线位置**：主课程 U7 第 1 课（prerequisites：L13），建议 45 分钟，含动手实验（[旋转曲面生成](#/lab/procedural-lathe)）。

## 1. 从一个问题开始

传统流程：美术在 Blender 建模 → 导出 FBX/glTF → 引擎读顶点与索引。这条链路成熟，但有个前提——**你必须先有一个模型**（[主文档 §3](../../../07-3D渲染与算法实现/程序化几何与旋转曲面.md#3-问题引入为什么不用模型文件)）。

现在需求变了：车机展示页要一个可交互的花瓶，用户拖动滑杆改瓶身曲线；管道场景要按路径实时生成栏杆。难道每次改参数都回 Blender 重导一遍？

换个起点：**如果形状本身可以用数学描述，为什么还要存一份顶点表？** 圆柱、花瓶、球冠、管道这类回转体，本质是一条二维轮廓绕轴旋转（断言 `V57`）。这一章把"参数 → 顶点 → 索引 → 画面"的全链条推一遍——这是你第一次亲手生产顶点数据，L13 的坐标数学在这里落地。

## 2. 学习前提

- **L13**：坐标空间链与 MVP——本章生成的顶点仍在**模型空间**（`V17`），最终要套 MVP 才到屏幕。
- **L08**：管线阶段——顶点缓冲/索引缓冲喂给顶点着色器的那一步，本章自己生产数据。
- 术语先给一句话解释（程序化几何 / 参数曲面 / 旋转曲面 / 顶点缓冲 / 索引缓冲 / 细分 / 网格在 `tools/glossary.json` 有权威术语卡）：
  - **母线 / 轮廓（profile）**：一条二维曲线 `(r, y)`——r 是到旋转轴的距离，y 是高度。
  - **径向分段 N**：绕轴一圈复制多少份；**轮廓采样 M**：沿母线取多少个点。

## 3. 直观认识

想象**陶艺拉坯**：泥团绕轴旋转，手指贴着一条轮廓曲线刮过去——曲线是什么形状，坯就是什么形状。轮廓上每个点 `(r, y)` 绕 Y 轴画出一个圆，一个个圆叠起来就是曲面（[主文档 §6 图示](../../../07-3D渲染与算法实现/程序化几何与旋转曲面.md#6-图形演示)）：

```
   y
   ↑        ● (r,y) 轮廓点
   |       /|
   |      / | 绕 Y 轴旋转 → 半径 r 的圆
   |     /  |
   +---------→ r
```

> **类比的边界**：拉坯是连续成型，GPU 网格是离散采样——圆只取 N 个点、轮廓只取 M 个点，所以"平滑"是采样密度的结果，不是数学曲面的本性（§4.3 的成本账）。类比也覆盖不了法线：真实光照需要每个顶点的法线方向，拉坯的直觉给不了它（§4.4 误区二）。

## 4. 一步一步理解原理

### 4.1 参数方程：每个参数控制什么（objective ①）

轮廓上一点 `(r(t), y(t))` 绕 Y 轴旋转角 θ 后（[主文档 §5](../../../07-3D渲染与算法实现/程序化几何与旋转曲面.md#5-数学原理参数方程)，断言 `V57`）：

$$
P(\theta, t) = \big(r(t)\cos\theta,\;\; y(t),\;\; r(t)\sin\theta\big), \quad \theta \in [0, 2\pi)
$$

- **符号含义**：t 是轮廓参数（沿母线从底到顶，可弧长归一化到 [0,1]）；θ 是绕轴角度，等分 N 份：θⱼ = 2πj/N；**r(t) 决定这一圈的半径，y(t) 决定它的高度**——checkpoint ② 的答案就在这两个函数里。
- **数值算例**：圆柱 = `r(t) = R`（常数）、`y(t) = t·H`——半径 R、高 H 的圆柱侧面；花瓶 = r(t) 随 t 先增后减。**换掉 r(t) 和 y(t)，同一个生成函数产出完全不同的形状**——这正是程序化的价值。
- **工程后果**：参数（半径/分段/轮廓）可以暴露给用户或着色器实时调整；代价是改公式就要重新生成缓冲。

### 4.2 从轮廓到 M×N 顶点与两组索引（objective ②）

**顶点**（[主文档 §7.1](../../../07-3D渲染与算法实现/程序化几何与旋转曲面.md#71-顶点缓冲)，断言 `V58`）：M 个轮廓点各复制 N 份 → **M×N 个顶点**；展开成一维缓冲的映射是 `k = i·N + j`（第 i 环第 j 列）：

$$
v_{i,j} = \big(r_i \cos\theta_j,\;\; y_i,\;\; r_i \sin\theta_j\big)
$$

**索引**（[§7.2](../../../07-3D渲染与算法实现/程序化几何与旋转曲面.md#72-索引缓冲)）：相邻两环 i 与 i+1 之间、第 j 列构成一个四边形，拆成两个三角形。四个角点：

$$
a = iN + j,\quad b = iN + (j{+}1)\bmod N,\quad c = (i{+}1)N + j,\quad d = (i{+}1)N + (j{+}1)\bmod N
$$

三角形取 **(a, c, b) 与 (b, c, d)**。注意 `(j+1) mod N`——最后一列要绕回第 0 列，圆环才闭合。**绕序决定法线朝向**，这是源文档标注 ⚠️ 的部分：不同 API 的正向定义不同，需按渲染管线调整（L13 的跨 API 差异在这里再次出现）。

### 4.3 细分的成本账（objective ③）

四个量的公式（[主文档 §7.3 表](../../../07-3D渲染与算法实现/程序化几何与旋转曲面.md#73-成本)，断言 `V58`）：

| 量 | 公式 |
|---|---|
| 顶点数 | M × N |
| 四边形数 | (M − 1) × N |
| 三角形数 | 2 × (M − 1) × N |
| 索引数 | 6 × (M − 1) × N |

- **符号含义**：M = 轮廓采样数（环数），N = 径向分段数（每环点数）；环间才有四边形，所以是 M−1。
- **数值算例**：M=10、N=8 → 顶点 80、三角形 2×9×8=144；**N 从 8 提到 48 → 三角形数线性增长 6 倍**（checkpoint ① 的答案：N 翻倍三角形数翻倍，因为公式对 N 是线性的）。
- **工程后果**：平滑度换来的是实打实的几何成本——**细分不是越多越好**，N 足够让轮廓在屏幕上看起来平滑即可（源 §9 误区一）；按距离调 N/M 就是 LOD（源 §10）。

### 4.4 GPU 执行与三个误区

执行链（[主文档 §8](../../../07-3D渲染与算法实现/程序化几何与旋转曲面.md#8-gpu-执行过程)）：CPU 调 `lathe(profile, N, M)` 生成 positions/indices → 上传 VBO/IBO → 顶点着色器套 `gl_Position = P·V·M·vec4(aPosition, 1)`（L13 的 MVP）→ 光栅化。**关键认知：几何在 CPU 生成一次，之后和模型文件走完全相同的渲染管线——程序化改变的是数据来源，不是渲染方式**（断言 `V59`）。

三个误区（源 §9 原文口径）：

1. **"细分越多越好。"** 过度细分在低端 GPU 上是浪费（§4.3）。
2. **"程序化几何不需要法线。"** 要参与光照就必须有法线——旋转曲面的解析法线可由偏导叉积得到，或由 GPU 在几何阶段计算。
3. **"把生成代码放进片元着色器。"** 几何生成通常以顶点为单位一次性完成；逐片元重算是另一类技术（如 SDF ray marching），不要混为一谈。

适用边界（源 §10，checkpoint ③）：回转体机械件/管道/栏杆/地形/可参数化建筑构件/需要 LOD 的场景适合；**角色、复杂有机形体不适合——仍以美术资产为主**。程序化与传统模型是**互补的两种数据表示**，不是替代关系（源 §3 原文）。

## 5. 数学原理 / 数据形态

把 §4 的推导合起来，就是实验里那段生成代码的数学骨架（伪代码与源 §7/实验 code 一致）：

```
for i in 0..M-1:            # 每个轮廓点
  for j in 0..N-1:          # 绕轴复制 N 份
    θ = 2πj/N
    positions[i*N+j] = (r_i·cosθ, y_i, r_i·sinθ)
for i in 0..M-2:            # 相邻环之间
  for j in 0..N-1:
    a=i*N+j; b=i*N+(j+1)%N; c=(i+1)*N+j; d=(i+1)*N+(j+1)%N
    indices += (a,c,b), (b,c,d)
```

数据形态：positions 是 M×N×3 个浮点数，indices 是 6×(M−1)×N 个整数——**索引数约为顶点数的 6 倍量级**（M 大时），这就是索引缓冲存在的意义：顶点只存一份，三角形靠索引复用（L08 的顶点/索引分工在这里亲手验证）。

## 6. 工程应用与常见错误

**工程现场**（由源 §3/§10 重组的教学案例）：展示页花瓶要支持用户改曲线。方案：轮廓做成数据驱动的控制点数组，运行时插值采样 → lathe 重新生成 → 上传缓冲。改参数 = 改数组，不回 Blender。性能配套（源 §10）：多个程序化网格合并减少 draw call（L14 批处理）；按距离调 N/M 做 LOD；低端设备上 N 取"屏幕看起来平滑"的下限而不是上限。

常见误区：

- **"程序化几何能替代美术资产。"** 互补不是替代；角色/有机形体仍靠美术（`V57`/`V59`，§4.4）。
- **"N 越大越好。"** 三角形数随 N 线性增长，平滑够用即可（`V58`，§4.3）。
- **"索引随便连。"** 绕序决定法线朝向，跨 API 正向定义不同 ⚠️；最后一列要 mod N 闭合（§4.2）。
- **"生成逻辑放片元着色器更灵活。"** 那是 SDF ray marching 另一类技术；网格生成通常以顶点为单位一次完成（§4.4）。
- **"程序化网格走特殊渲染路径。"** 生成后与模型文件走完全相同的管线（`V59`，§4.4）。

## 8. 总结与主动回忆

合上文档，复述这条因果链（说不出来就回到对应小节）：

**回转体 = 二维轮廓绕轴旋转 → 参数方程 P(θ,t)=(r·cosθ, y, r·sinθ)，r 管半径 y 管高度（`V57`）→ M 轮廓点 × N 径向分段 = M×N 顶点，k=i·N+j；相邻环四边形拆 (a,c,b)/(b,c,d) 两三角形，mod N 闭合，绕序定法线 ⚠️（`V58`）→ 三角形数 2(M−1)N 对 N 线性：细分买平滑也买成本，LOD 按距离调 N/M（`V58`/`V59`）→ CPU 生成一次，之后与模型文件同管线；法线不可少；角色有机形体仍靠美术（`V59`）。**
