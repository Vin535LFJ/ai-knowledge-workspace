# 光照、材质与图像算法

> **本章回答**：画面发灰、阴影漏光、边缘锯齿分别属于哪一层的问题？
> **写作纪律**：正文用自己的语言展开机制，权威定义与完整细节链接主文档锚点；陌生术语首次出现给出一句话解释。
> **路线位置**：主课程 U5 第 2 课（prerequisites：L13），建议 50 分钟。本章无绑定实验（PBR 交互实验绑定在 L18，本章不预占），动手形式为归层决策练习 + A/B 观察（§7）。

## 1. 从一个问题开始

车模查看器上线前，测试报了三条 bug：

1. 金属车漆**整体发灰**，像蒙了层雾；
2. 车轮与地面接触处**阴影漏光**，影子边缘一条亮缝；
3. 远处地面纹理**闪烁**，车一动就"沙沙"地跳。

三个症状看起来都是"画面不对"，但修法完全不同——因为它们发生在**不同的层**：第一个在色彩管线，第二个在阴影算法，第三个在纹理采样。把它们混在一起调，就会陷入"调了这个坏了那个"的循环。这一章给你一张**分层地图**：光照、材质、后处理、采样、提交各管什么，问题先归层、再动手（断言 `V47`）。

## 2. 学习前提

- **L03**：线性工作流与 sRGB——"发灰"的病理学基础（[色彩管理 §1.3](../../../03-图形与GPU工程/色彩管理与采样滤波.md#13-线性工作流)）。
- **L09**：MSAA 与几何锯齿（断言 `V38`）——本章要区分"两种锯齿"。
- **L08/L13**：管线阶段与坐标空间——阴影贴图要把世界坐标变到光源空间（L13 的 MVP 在这里复用）。
- 术语先给一句话解释（PBR / BRDF / 采样 / mipmap / MSAA / DrawCall 在 `tools/glossary.json` 有权威术语卡）：
  - **LUT**（Look-Up Table，查找表）：把"输入颜色→输出颜色"的映射预先存成表，运行时查表调色。
  - **降噪**：去掉图像噪声（颗粒/杂点）的算法；**超分**：把低分辨率图像放大到高分辨率并尽量补回细节。
  - **tone mapping**（色调映射）：把 HDR 光照结果压缩到显示设备能呈现的范围。
  - **Instancing**（实例化）：同一网格一次提交画 N 份，每份带自己的变换/参数。

## 3. 直观认识

用**摄影**类比整条链：**光照**是布光（光怎么打到物体上），**材质**是物体表面的质地（金属还是磨砂塑料），**阴影**是布光产生的遮挡关系，**后处理**是拍完之后的修图（调色/锐化/降噪），**批处理**则是摄制组的调度物流（多少趟车把道具运到片场——发生在拍摄之前）。

> **类比的边界**：修图改不了布光物理——后处理是屏幕空间操作，不改变几何与光照计算本身；修图也救不回失焦的照片——信息损失不可逆，生成式超分"补"出的细节可能是**伪细节**（源 §9.1 GAN 行原文：可能生成伪细节）。调度物流（批处理）与画面内容无关，它优化的是 CPU 提交成本。

## 4. 一步一步理解原理

### 4.1 BRDF 与 PBR 的关系（objective ①）

光照模型的演进（[光照材质 §1 表](../../../07-3D渲染与算法实现/光照材质与阴影.md#1-光照模型的演进)，断言 `V46`）：

| 模型 | 公式核心 | 解决什么 | 遗留问题 |
|---|---|---|---|
| Lambert | `diffuse = N·L` | 漫反射随角度衰减 | 无高光、无能量守恒 |
| Phong | `spec = (R·V)^shininess` | 加高光 | 高光在低模上断裂 |
| Blinn-Phong | `spec = (N·H)^shininess` | 半角向量更便宜、更平滑 | 仍非物理 |
| PBR | 微表面 BRDF | 能量守恒、材质参数可测量 | 计算/带宽更贵 |

**BRDF**（双向反射分布函数）是描述"表面某点，光从某方向来、往某方向去，反射多少"的数学函数。现代 PBR 的主流实现是微表面 Cook-Torrance 分解：漫反射项 + 镜面项 `D·G·F / 4(N·L)(N·V)`——D 管微表面法线分布（多少微面朝向半角）、G 管微面互相遮挡、F 管菲涅尔（入射角越大反射越强）（[§3.1](../../../07-3D渲染与算法实现/光照材质与阴影.md#31-cook-torrance-分解)）。公式逐项推导与参数实验在 [L18](L18-PBR光照与材质参数.md) 展开，本章先建立定位。

**checkpoint ① 的答案：PBR 是一组模型约束，不是一组 shader。** 约束是：能量守恒（反射光不超过入射光）、参数有物理含义且可测量（roughness = 微表面法线分布宽度，不是"调到好看"的高光强度）、光照计算在线性空间（§4.2）。任何满足这组约束的实现都算 PBR——Cook-Torrance 只是其中一种主流实现（源 §1 面试要点与 §10 Q1 口径）。一个立刻能用的推论：**metallic=1 时 diffuse 必须为 0**——金属的自由电子吸收透射光，只剩表面反射；给金属加漫反射，它会看起来像"发亮的塑料"（源 §3.3 常见错误原文）。

### 4.2 画面问题归层（objective ②）

先立三条铁律（[光照材质 §2.1](../../../07-3D渲染与算法实现/光照材质与阴影.md#21-三条铁律)）：光照计算必须在**线性光强**空间；albedo 是 sRGB 而法线/粗糙度/金属度/AO 是**线性数据**不能设 sRGB；光照结果经 tone mapping 再编码到显示空间，不能把 HDR 值直接写进 8bit sRGB 附件。

然后给 §1 的三个症状归层（断言 `V47`）：

| 症状 | 所属层 | 机制与出处 |
|---|---|---|
| 整体发灰 | 色彩管线 | 最常见"双重 gamma"或"缺失 gamma"：线性值又手动 `pow(1/2.2)`，或线性渲染后直接输出没编码（[色彩管理 Q1](../../../03-图形与GPU工程/色彩管理与采样滤波.md#q1为什么画面整体发灰)） |
| 阴影漏光 | 阴影算法 | shadow map 深度比较的 bias 不当：常数偏移在斜面/远处漏光或悬浮；bias 调大消自阴影但产生"彼得潘现象"（影子分离），**没有一劳永逸的参数，按场景调** ⚠️（[光照材质 §5.2](../../../07-3D渲染与算法实现/光照材质与阴影.md#52-偏差bias)） |
| 远处纹理闪烁 | 纹理采样 | 缺 mipmap（预生成的逐级减半纹理链）或不完整，缩小采样 aliasing（[色彩管理 Q3](../../../03-图形与GPU工程/色彩管理与采样滤波.md#q3为什么远处纹理闪烁)） |
| 几何边缘锯齿 | 光栅化覆盖 | 三角形边缘的覆盖锯齿——MSAA 的领域（L09 `V38`），与上一行是**两种不同的锯齿** |

归层的意义：发灰去查纹理/帧缓冲格式与后处理链的重复转换，漏光去调 bias，闪烁去查 mip 链——**三条 bug 三个工位，互不干扰**。

### 4.3 mipmap 解决的是哪种锯齿（checkpoint ②）

**缩小（minification）必须用 mipmap**：纹理分辨率高于屏幕覆盖时，一个像素要"代表"一大片纹素，直接点采样会欠采样——摩尔纹/闪烁（[色彩管理 §2.2](../../../03-图形与GPU工程/色彩管理与采样滤波.md#22-放大与缩小)，断言 `V48`）。mipmap 预先生成逐级减半的纹理链，采样时按覆盖范围选层：

$$
\text{lod} = \log_2\left(\max(|\text{dFdx}(uv)|, |\text{dFdy}(uv)|) \times \text{texSize}\right)
$$

- **符号含义**：dFdx/dFdy 是屏幕空间导数（相邻像素间 UV 的变化量），texSize 是纹理边长——lod 即"一个像素覆盖多少纹素"取对数。
- **数值算例**（教学算例）：一个像素覆盖 4×4 纹素 → lod = log₂4 = 2，选第 2 级 mip（分辨率已减半两次）。
- **工程后果**：mip 链不完整或 LOD bias 不当 → 闪烁；但 mip 也有坑——图集串色（mip 层把相邻图块混合）、文字发糊（UI 应关 mipmap 或提分辨率）（[§2.3 坑表](../../../03-图形与GPU工程/色彩管理与采样滤波.md#23-mipmap-的坑)）。斜视地面还要各向异性过滤（§2.4）——成本随采样数增长，移动端常用 2×/4×，受 `GL_MAX_TEXTURE_MAX_ANISOTROPY_EXT` 限制。

**checkpoint ② 的答案：mipmap 解决采样稳定性（缩小 aliasing），不是几何边缘锯齿。** 几何锯齿是三角形覆盖问题，靠 MSAA（`V38`）；纹理闪烁是采样欠采样问题，靠 mipmap。两者都叫"锯齿/aliasing"，但病灶和药都不同——这正是 §4.2 归层表最后两行要分开的原因。

### 4.4 后处理地图与管线位置（objective ③ 前半）

后处理 = **着色完成之后、显示之前**的屏幕空间（或帧序列）操作（[GPU 图像算法](../../../07-3D渲染与算法实现/GPU图像处理算法.md)，断言 `V49`）：

| 算法族 | 解决什么 | 关键取舍 |
|---|---|---|
| 3D LUT 调色（§4） | 风格化色彩映射 | 查表便宜；采样要点见源 §4.2 |
| 锐化（§5） | 放大/压缩后的细节恢复 | CAS（对比度自适应锐化）等方法 |
| 降噪（§6） | 颗粒/杂点 | 空间域（高斯糊/双边保边/NLM 非局部均值高质量很贵）；时域 TAA（时域抗锯齿）/TNR（时域降噪）重用历史帧，**运动矢量必须含相机+物体运动，遮挡区要拒绝历史帧否则鬼影** |
| Debanding/Dithering（§7） | 8bit 量化色带 | 抖动幅度约 1 个量化步长；**sRGB 编码后、写 8bit 前加，顺序错了无效** |
| 超分（§9） | 低分辨率源放大 | 空间插值便宜；CNN/GAN 需 NPU（神经网络加速器）；**通常增加 1–2 帧延迟**；生成式可能改变语义（车牌/文字），功能安全场景禁用 ❗（源 §9.3） |

降噪选择（源 §6.3）：视频播放实时降噪 = 轻量空间滤波 + 时域可选；光追 = 时空降噪；相机预览 = 平台 ISP 已做、应用层避免重复；离线导出 = BM3D/NLM 质量优先。处理域也有讲究（源 §10）：亮度降噪/锐化在 **Y 域**（避免放大色度噪声），色调映射在线性 RGB，字幕/UI 叠加在 RGB（避免色度子采样彩边）。

### 4.5 批处理是 CPU 侧的活（objective ③ 后半）

批处理与上面所有算法**不在同一个位置**：它发生在 GPU 执行**之前**，优化的是提交成本（[批处理 §1](../../../07-3D渲染与算法实现/批处理与GPU驱动管线.md#1-drawcall-成本到底花在哪)，断言 `V50`，复用 L08 `V07`）。DrawCall 成本五行表（源 §1）：应用层遍历/排序/组装（CPU）、驱动校验（CPU）、提交（CPU）、GPU 前端状态切换（GPU）、GPU 执行（GPU）。**100 个与 10000 个 DrawCall 的差别主要在前三行**；单个 DrawCall 三角形很多时成本被 GPU 执行淹没，很少时 CPU 提交占主导。所以"合批不是目的，降低每帧的提交次数与状态切换次数才是"（源原文）。

四代方案（源 §2 表）：静态合批（烘焙大 VBO，代价显存膨胀/失去单体剔除）→ 动态合批（每帧 CPU 变换小网格）→ Instancing（同网格同材质画 N 份，**顶点着色器仍执行 N 次，只是省了提交**）→ 间接/GPU 驱动（绘制参数由 GPU 生成，需显式 API 或扩展——L10 的知识在这里接上）。桌面驱动的多线程命令录制摊薄了 CPU 成本，移动端 GLES 驱动偏单线程，合批收益更明显 ⚠️（源 §1）。

配套治理：PSO 预热与变体裁剪（源 §9，L10 §4.5 的延续）——n 个布尔关键字理论变体 2ⁿ，再乘平台/画质档位/顶点布局/开关，中等项目轻松数千变体；**治理的核心不是"全部编译"，而是"知道哪些组合真的会出现"**（源 §9.3 ✅）。

## 5. 数学原理 / 数据形态

把本章所有角色放进一张管线位置图（教学重组，各环节出处见 §4）：

```
CPU 侧：场景遍历 → 合批/Instancing → PSO/绑定 → 提交      ← V50/V07（批处理）
GPU 侧：顶点 → 光栅化（MSAA 覆盖）→ 片元着色              ← 光照/材质（V46）+ 阴影
        → 后处理 Pass（LUT/锐化/降噪/超分）               ← V49（屏幕空间）
        → tone mapping → sRGB 编码 → dither → 写 8bit/显示   ← 色彩管线（V47）
纹理采样贯穿片元阶段：mipmap/各向异性                      ← V48
```

变体账（源 §9.3 公式，三件套）：

$$
N_{\text{variants}} = 2^n \times (\text{平台} \times \text{档位} \times \text{布局} \times \text{开关})
$$

- **符号含义**：n = 独立布尔 shader 关键字数。
- **数值算例**（教学算例）：n=10 → 1024 组合；乘 2 平台 × 3 档位 = 6144——还没算布局与开关。
- **工程后果**：必须变体裁剪 + 预热 + 缓存，否则运行时首建 PSO 卡顿（L10 §4.5 的几十到几百毫秒会在这里集中爆发）。

## 6. 工程应用与常见错误

**排查现场**（由色彩管理 Q1/Q3 与光照材质 §5.2 重组的教学案例）：回到 §1 的车模查看器。三条 bug 按归层表分头处理：发灰 → 查后处理链发现 tone mapping 后又手动做了一次 gamma 编码（双重 gamma），删掉重复转换；漏光 → 常数 bias 改斜率偏移 `max(0.05*(1-N·L), 0.005)`，按场景尺度微调（源 §5.2 表）；地面闪烁 → 生成完整 mip 链 + 三线性过滤 + 斜视地面开各向异性。三条各自闭环，互不牵连——这就是归层的价值。

常见误区：

- **"PBR 就是一套 shader。"** 是一组模型约束（能量守恒/可测量参数/线性空间），实现可换（`V46`，§4.1）。
- **"画面不对就调后处理。"** 先归层：发灰在色彩管线、漏光在阴影、闪烁在采样——后处理救不了上游错误（`V47`，§4.2）。
- **"mipmap 能抗所有锯齿。"** 它治缩小采样的摩尔纹/闪烁；几何边缘锯齿是 MSAA 的领域（`V48`/`V38`，§4.3）。
- **"超分无代价。"** 1–2 帧延迟 + 生成式伪细节风险；倒车影像/功能安全场景禁用生成式（源 §9.3 ❗，§4.4）。
- **"Instancing 免费。"** 顶点着色器仍执行 N 次，省的只是提交（源 §2.3，§4.5）。
- **"阴影 bias 调一次管所有场景。"** 自阴影与彼得潘现象两头拉扯，只能按场景调 ⚠️（源 §5.2）。

## 8. 总结与主动回忆

合上文档，复述这条因果链（说不出来就回到对应小节）：

**光照模型从 Lambert 走到 PBR：BRDF 描述表面反射，PBR 是能量守恒 + 可测量参数 + 线性空间的模型约束（`V46`）→ 画面问题先归层：发灰=色彩管线、漏光=阴影 bias、纹理闪烁=mipmap、几何锯齿=MSAA（`V47`/`V38`）→ mipmap 治缩小采样稳定性，不治几何边缘（`V48`）→ 后处理在着色后显示前：LUT/锐化/降噪/超分各有质量-延迟取舍，生成式超分有语义风险（`V49`）→ 批处理在 GPU 执行前：降提交与状态切换次数，四代方案 + 变体治理（`V50`/`V07`）。**

再自问三个"为什么"：为什么金属没有漫反射？为什么时域降噪必须拒绝遮挡区的历史帧？为什么"合批不是目的"？
