# Learning Experience Design · 操作指南（USAGE）

> 这是给**操作者**的快速指南：怎么让 Agent 用这个 Skill 改一个页面、怎么验收。
> 完整设计规范在 `SKILL.md` 与 `references/`；本文不重复正文，只给流程、命令、提示词和边界。

---

## 1. Skill 的作用

把 Engine 的学习站从「Markdown 渲染」提升为**可发现、可理解、可验证、可记住**的技术学习产品。它管的是**呈现与学习体验**：

- 信息架构与阅读节奏
- 教学可视化（结构图、数据流、时间轴、对比表、推导）
- 页面原型（知识文章 / 系统教材 / 技术推导 / 交互实验 / 知识图谱 / 研究报告）
- 视觉质量门槛（Floor / Reflex / Finish）
- 响应式与无障碍

它**不生产知识**，也不改数据模型。

## 2. 适用范围

- 新建或改造教材页、知识文章页、实验页、图谱页、研究报告页。
- 给现有页面加「学习目标条、前置知识、术语卡、推导表、自测入口、上下章桥」。
- 做页面视觉审查、响应式与键盘可达性检查。
- 为某个知识类型选择更合适的表达方式（图/表/推导/交互）。

## 3. 不适用范围

- **纯内容事实修订**：走 KCR / claim-ledger，不归本 Skill。
- **构建脚本、数据结构改造**：走 `tools/`。
- **网站功能 bug**（搜索坏了、路由错）：走工程流程。
- **品牌/营销页**：本 Skill 明确反对 SaaS 落地页套路。
- **新建独立站点或内容库**：本 Skill 消费现有 `course.json` / `glossary.json` / `labs.json` / `graph.json`，不另建。

## 4. Agent 如何调用

发现链（当前真实）：

1. 仓库根 `AGENTS.md` / `CLAUDE.md` → 指向 `.agent/README.md`。
2. `.agent/README.md:67` 列出 `skills/learning-experience-design/`。
3. 进入 `SKILL.md` 读取工作流与门槛。

调用方式：本 Skill 没有 `disable-model-invocation`，属 **model-invoked**，模型可在「设计/优化学习页面」类请求中自动使用；也可以由人显式说「用 learning-experience-design」。

> **限制**：AGENTS.md 不直接列 Skill 名；如果 Agent 不读 `.agent/README.md`，发现链会断。可在 AGENTS.md 补一行索引（建议）。

## 5. 输入要求

至少提供：

| 输入 | 必填 | 说明 |
|---|---|---|
| 目标页面路径 | 是 | 例如 `courses/video-rendering-journey/lessons/L13-坐标变换与MVP.md` |
| 页面类型 | 是 | A–F（见 §8），或让 Agent 判定 |
| 学习者任务 | 是 | 学完能做什么（来自 frontmatter objectives） |
| 约束 | 是 | 不改事实/不改断言状态/不改生成物/不建新库 |
| 现有数据 | 建议 | 该课的 `claims`、`lab`、术语、上下章 |
| 参考页面 | 可选 | 例如 L01（Gold Standard）或 L13（试点） |

## 6. 输出要求

一次合格的产出应包含：

1. **页面规格**（用 `assets/page-spec-template.md`）：原型、目标、结构、必备区块、反模式规避。
2. **改动**：只改目标页与其必要的 JSON 联动；正文事实零改动。
3. **前后对照**：改了什么、为什么、影响哪些门禁。
4. **Floor 结果**：`check_visual_floor.py` 输出。
5. **审查记录**（用 `assets/design-review-template.md`）：Floor/Reflex/Finish 逐项结论。
6. **偏差说明**：做不到的（例如零依赖不能上 Mermaid）如实写。

## 7. 标准设计流程

1. **读页面与数据**：frontmatter、正文结构、claims、lab、术语、上下章。
2. **定原型**：A–F 选一个主原型，允许兼容一个次原型。
3. **写规格**：目标 / 学习者任务 / 结构 / 必备区块 / 不改清单。
4. **做最小改动**：优先用现有组件与 CSS 变量；不新增依赖。
5. **跑静态检查**：

```powershell
py -3 .agent/skills/learning-experience-design/scripts/check_visual_floor.py "courses/video-rendering-journey/lessons/Lxx-*.md"
```

6. **跑站点门禁**：

```powershell
py -3 tools/build_site.py
py -3 tools/validate_site.py
```

7. **真浏览器验收**：本地起服务，360/768/1280 三档宽度；键盘走一遍；明暗主题各看一次。
8. **记录**：审查模板 + 偏差 + 门禁数字。

## 8. 页面类型

| 原型 | 目标 | 关键结构 | 典型页面 |
|---|---|---|---|
| A 知识文章 | 查漏补缺、理解单点 | 钩子→定义→例子→原理→关系→来源→术语 | 01–07 主文档 |
| B 系统教材 | 完成认知闭环 | 目标→问题→前置→直观→概念→推导→机制→实践→迁移→下一章 | L01–L19 |
| C 技术推导 | 看懂「为什么」并能自己推 | 假设→变量→分步推导→算例→工程意义→常见错误 | L13 MVP、L19 PQ |
| D 交互实验 | 动手验证 | 目标→前置→控件→实时反馈→任务→记录→自测→原理 | 7 个 labs |
| E 知识图谱 | 探索关系与路径 | 入口→重点节点→依赖→推荐路径→详情→筛选 | `M` 视图 |
| F 研究报告 | 证据与结论 | 问题→方法→证据→结论→限制 | `reviews/*` |

**规则**：一页一个主原型；不要把所有页面做成同一种卡片流。

## 9. 设计原则（操作层）

1. **消费现有数据**：`course.json` / `glossary.json` / `labs.json` / `graph.json` / `evidence/`，不建第二份。
2. **图为了理解**：每个图必须回答一个具体问题；不默认塞图和卡片。
3. **公式要能读**：用 `$$` 块；变量表 + 每步一句理由；长公式可横向滚动。
4. **术语首现给一句话**：再链到术语卡。
5. **不制造虚假内容**：数字、来源、断言状态必须来自台账；不确定就写「待核实」。
6. **沿用变量体系**：明暗主题 + CSS 变量；不硬编码颜色。
7. **移动端 360px 不溢出**；必要操作不隐藏。
8. **键盘可达、焦点可见**；不用 `outline:none` 无替代。
9. **反 AI 模板**：不要每个标题上方一条 eyebrow、不要无意义渐变/玻璃拟态、不要所有页面同模板。
10. **改动最小**：能加一段就不重排全页；能复用组件就不新建。

## 10. 页面审核标准

### Floor（硬阻塞，不清零不发布）

- 正文 ≥15px、行高 ≥1.6、对比度 AA。
- 键盘全流程可达、焦点可见。
- 360px 无横向溢出，必要操作不隐藏。
- 公式/代码/图不溢出、不截断。
- 不破坏现有 7 个实验、搜索、术语、课程、图谱、反馈。
- 不遗漏自测、实验入口、上下章导航。
- 不编造内容与断言状态。

### Reflex（默认倾向，可豁免但需记录理由）

- 避免重复卡片、卡片套卡片。
- 避免滥用渐变/玻璃拟态/发光阴影。
- 避免所有页面同模板、标题上方 eyebrow。
- 不随意改正文阅读宽度。
- 避免多余装饰。

### Finish（不阻塞发布）

字体细节、动画、图表过渡、微交互、精细间距、页面一致性。

### 可执行检查

```powershell
# 静态前置（标题层级/outline:none/硬编码色/主题变量/生成物引用）
py -3 .agent/skills/learning-experience-design/scripts/check_visual_floor.py "<页面>"

# 文档结构
py -3 tools/validate_site.py
py -3 .workbuddy-ai/skills/research-to-learning/scripts/check_chapter_arc.py "<页面>"
```

> `check_visual_floor.py` **只做静态检查**，不替代浏览器截图与人工裁决。

## 11. 如何改善现有页面

1. 选页面：优先「高价值 + 结构完整 + 缺可视化/节奏」的页面（L13 就是这样选的）。
2. 记录基线：当前 Floor 结果、字数、结构、已有图表。
3. 列 3–6 条最小增强（不要重写）：目标条、前置链、推导表、术语绑定、自测入口、下一章桥。
4. 逐条实施，每改一条跑一次 Floor。
5. 做前后对照（同一浏览器、同一宽度）。
6. 更新页面规格与审查记录。
7. 不改事实、不改断言状态、不改 `web/content.js`。

## 12. 如何验证设计结果

| 层 | 方法 | 通过标准 |
|---|---|---|
| 静态 | `check_visual_floor.py` | exit 0 |
| 结构 | `validate_site.py` | 12/0/0 |
| 构建 | `build_site.py` | 文档/课/卡数符合预期 |
| 渲染 | `py -3 -m http.server 8791 --directory web` + 浏览器 | 页面可开、无控制台错误 |
| 响应式 | 360 / 768 / 1280 | 无横向滚动、操作可见 |
| 键盘 | Tab/Shift+Tab/Enter/Esc | 全流程可达、焦点可见 |
| 主题 | 明/暗 | 对比度合格、无不可读 |
| 内容 | 对照 claim 台账 | 数字/状态一致 |

落地的六项：

4. MVP 术语绑定 `tools/glossary.json`（两层 course.json + 术语卡）。

**如实偏差**：

- 试点 B（实验页反链）**未做**：涉及 `app.js` 回归面，单独裁决。

**L19**：只做了 Floor 静态检查（PASS），**没有做页面增强**。它是「跨课程 Floor 可运行」的第二个应用点，不是第二个优化案例。

**试点 02 · transform-mvp 交互实验页（2026-11-25，提交见 Engine CHANGELOG）**——第二个真实案例，页面类型是原型 D（交互实验），与试点 01 的教材页不同：

- 先用真实浏览器对**全部 7 个实验**做基线：三档宽度溢出、控件命名、明暗主题对比度、交互冒烟。
- 诊断：实验页不缺目标条 / 推导表 / 术语绑定，缺的是**实验目标、观察记录、键盘操作说明**；另有一处硬伤——浅色主题下承载内容的小字对比度 **3.04:1**（门槛 4.5:1），读代码看不出来，是测出来的。
- 落地：对比度修复（5 处，7 个实验共享，3.04 → 6.39:1）；动手任务复选框与文字关联（共享）；试点页实验目标 3 条 + 观察记录（本机保存）+ 键盘提示。
- 回归：7 个实验冒烟零报错，画布输出与分阶段数值与基线逐项相同。
- 未推广：其余 6 个实验的目标与观察记录等用户确认。完整记录、前后截图与原始测量数据见 `preview/PILOT-LAB-mvp.md`。

**结论**：成熟度是「两类页面各完成一次真实优化」（教材页、交互实验页），仍不是「多案例稳定复用」。两个案例说明同一套流程对不同页面类型会给出不同诊断。

**在 QwenWork 宿主的发现实测（2026-11-25）**：宿主技能目录**没有收录**本 Skill（按名称搜索无结果）；§4 的仓库内发现链三步都存在（根 `AGENTS.md` L16 → `.agent/README.md` L67 → `SKILL.md`）。调用方式是读取并遵循，不是宿主级技能加载。

## 14. 常见问题与限制

**Q1：为什么不能直接用 Mermaid？**
A：离线站零外部依赖；Mermaid 会引入打包/渲染依赖。用 ASCII 或现有 SVG/Canvas。

**Q2：能改 `web/content.js` 吗？**
A：不能，它是生成物。改源 Markdown/JSON，再 `build_site.py`。

**Q3：为什么 Floor PASS 了还不能发布？**
A：Floor 只是静态前置；还要浏览器多宽度、键盘、主题、人工视觉裁决。

**Q4：13 份 references 都要读吗？**
A：不必全读。最小集：`visual-quality-gates.md`、`design-system.md`、`learning-page-archetypes.md`、`educational-visualization.md`、`ux-review-checklist.md`。其余为补充/重叠（审计建议合并）。

**Q5：能把这个 Skill 用在别的项目吗？**
A：它是 Engine 内部 Skill，设计绑定 Engine 的数据文件与 CSS 变量。可以借鉴方法，但不要直接复制到别的站点当通用库。

**Q6：为什么只有两个试点？**
A：铁律 1 要求先做有代表性的试点、用户确认后再推广。两个试点分别是教材页（L13）与交互实验页（transform-mvp）；其余页面与实验的推广等用户确认。

**已知限制**：
- 无浏览器截图/多宽度回归的自动化，靠人工。试点 02 的测量脚本是一次性的（在临时目录），**没有入库**，原始测量数据已保存但脚本本身不可复跑；是否入库待用户裁决。
- 无视觉回归基线图（只有 checklist）。
- references 有 6 份以上主题重叠。
- L19 未做增强；实验页只做了 transform-mvp 一个，其余 6 个未做。
- Skill 在 QwenWork 宿主实测：技能目录未收录，只能经仓库入口指针发现。其他宿主未验证。
- 视觉模型对截图的描述不可靠（试点 02 中把浅色主题说成深色、把 3.04:1 说成"对比度尚可"）；可读性结论以像素取样与计算值为准。

## 15. 可复用提示词

### A. 新课程页面设计

```
用 learning-experience-design 设计 <页面路径> 的新页面。
先读 SKILL.md、lesson-quality-standard 与页面 frontmatter。
产出：页面规格（原型 A–F + 学习目标 + 结构 + 必备区块 + 不改清单）。
只做最小实现，消费现有 course/glossary/labs/graph 数据；不新增依赖；不改事实与断言状态。
完成后跑 check_visual_floor + build_site + validate_site，并给我前后对照。
```

### B. 现有页面优化

```
用 learning-experience-design 优化 <页面路径>，目标是 <阅读体验/推导可读性/术语理解/移动端>。
先给我 3–6 条最小增强建议与影响面，我批准后再改。
每条改完跑一次 check_visual_floor；最后做 360/768/1280 三档验收与键盘检查。
不要重写正文，不要改断言状态。
```

### C. 页面质量审核

```
用 learning-experience-design 审核 <页面路径>，只读，不改文件。
按 Floor / Reflex / Finish 输出逐项结论（通过/不通过/豁免理由），
并指出：结构缺口、可视化缺口、无障碍风险、移动端风险、与现有组件/规范冲突。
最后给「能否发布」的结论与最小修复清单。
```

### D. 跨页面一致性检查（可选）

```
抽查 <页面A> 与 <页面B>，比较：标题层级、阅读宽度、术语卡样式、公式块、上下章桥、实验入口。
列出不一致项与统一建议；不要直接改。
```
