# 试点 02 · transform-mvp 交互实验页（2026-11-25，真实浏览器基线 + 最小增强）

> 第二个真实案例。第一个案例（L13 教材页，2026-11-21）验证的是长文教材页；本案例验证 LXD 对**交互实验页（原型 D）**是否同样能指导诊断与修改。
> 执行依据：用户 2026-11-25 任务书 TASK 5（选一个真实交互实验页，用 LXD 诊断 → 最小修改 → 检查交互与响应式 → 前后对照 → 复盘）。
> 原始测量记录：`lab-mvp/baseline.json`、`lab-mvp/after.json`（7 个实验 × 三档宽度 × 明暗主题）；截图：`lab-mvp/before-*.png`、`lab-mvp/after-*.png`（1280 与 360 两档，浅色主题，像素取样确认背景为白）。

## 0. 结论

- **LXD 对交互实验页有效，但诊断结论与教材页不同**。教材页（案例 01）缺的是目标条、推导表、术语绑定；实验页这三样本来就有，缺的是**实验目标、观察记录、键盘操作说明**，外加一处测量才看得见的硬伤：**浅色主题下承载内容的小字对比度只有 3.04:1**（门槛 4.5:1）。如果照搬教材页的六项增强，会得出"实验页已经很好"的错误结论。
- 改动范围：1 处对比度修复（7 个实验共享样式）、1 处复选框关联（共享）、试点页的实验目标 + 观察记录 + 键盘提示。
- 回归：7 个实验交互冒烟零报错，画布输出字节数与分阶段数值**与基线逐项相同**，三档宽度均无整页横向滚动。
- **只改了一个实验页的目标/观察记录，未推广**（SKILL.md 铁律 1：用户确认后才推广）。

## 3. 诊断

**对照原型 D 的结构**（实验目标 → 前置概念 → 操作区 → 实时反馈 → 分步任务 → 观察记录 → 自测 → 关联原理）：前置概念（术语卡）、操作区与反馈区同屏、分步任务、自检、关联原理（回课文 + 原始文档）都有；**实验目标与观察记录两块在结构上就缺位**。

**对照签发单**：
- F1（正文对比 ≥4.5:1）：**不通过**——3.04:1。这靠读代码看不出来（样式变量名不体现用途），是测出来的。
- F2（键盘可达）：控件全部可聚焦且有名称，但没有告诉学习者"可以用键盘"。
- F3（四档不溢出）：通过。
- F4（明暗主题）：功能正常；对比度问题出在浅色。
- F6（不破坏交互）：通过。

## 8. 复盘：LXD 在这个案例里验证了什么

1. **原型分类有用**。按原型 D 的结构与必备项对照，直接定位到两块结构性缺口；同样这套流程用在教材页（案例 01）定位到的是另一些缺口。
2. **签发单把"看起来还行"变成了可判定的项**。对比度问题肉眼和代码审查都没发现，是按 F1 实测出来的。
3. **图像描述不能当测量**。我让一个视觉模型描述"优化前"截图，它说页面是深色主题、小字对比度尚可；对截图做像素取样，背景是纯白（浅色主题），计算对比度 3.04:1。可读性结论必须来自像素或计算，不能来自描述。
4. **最小增强可以在不改计算逻辑的前提下完成**：画布输出与分阶段数值前后逐字节相同，是最直接的"没改坏"证据。
