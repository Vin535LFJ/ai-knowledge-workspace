# PD-001 · 建立统筹 Program：索引而非迁移

- 日期：2026-11-19
- 状态：accepted（用户本轮指令："先建一个大文件夹……统筹规划四个项目的计划、执行情况和实际进度……包含在文件夹里面或者做好索引也行"）
- **注：本决策的"索引而非迁移"位置策略已被 PD-002（2026-11-19）取代——四项目已物理集中到 `AI-Knowledge\` 父文件夹。建立统筹办公室本身仍有效。**
- 决策人：用户；执行：qwenwork

## 背景

四项目已实际存在（CHG-0001 后）：Render_Notes 与两个新项目在 `Desktop\GITCODE\`，skills 库在 `E:\AI-Tools\`。
跨项目计划、进度、监督无统一入口；已发生多 Agent 写入漂移事故。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A 物理迁移四项目进大文件夹 | 目录集中 | 移动活跃 git 仓库；Render_Notes 治理文档/门禁命令/远程配置内嵌大量绝对与相对路径，迁移即破坏；跨盘移动 E:\ 仓库风险高 |
| **B 大文件夹 + 绝对路径索引（采纳）** | 零迁移风险；统筹层独立版本化；符合"可迁移不强耦合" | 索引需随迁移维护（以本索引为唯一位置权威 + 迁移必改索引的规则对冲） |
| C 不建文件夹，只在 Render_Notes 内加统筹文档 | 无新仓库 | 统筹层与核心产品耦合，违背引导文档边界；Render_Notes 已承载过多治理 |

## 决策

1. 建 `C:\Users\Giant\Desktop\GITCODE\ai-knowledge-program`（与 3/4 项目同区）作为统筹办公室。
2. 四项目**保持原位置**，以 `PROJECT_INDEX.md` 为唯一位置权威；不做物理迁移。
3. 本仓库只存计划/索引/快照/程序级决策/交接指针，不复制知识与 Skill 正文。
4. 本地 git 版本化；远程创建另行授权（PD-Q3）。
5. 未来新建项目默认放本文件夹 `projects/` 下或 GITCODE 同区，登记索引即可。

## 后果

- 任何 Agent 进入 Program 先读 README；位置变更必须先改索引并记 PD。
- 看板与项目内状态文档冲突时以项目内 + git 实测为准（单一事实源规则）。
