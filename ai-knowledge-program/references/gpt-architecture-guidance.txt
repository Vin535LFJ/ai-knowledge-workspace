Engine 完成验收标准
1. 原始资料可以通过统一输入接口进入工作流。
2. Research Agent 能生成有可靠来源、证据和争议记录的深度研究报告。
3. Evidence 和 Knowledge Architect 能完成知识点提取、查重、关系构建和冲突识别。
4. Documentation Writer 能将知识转化为完整的系统教材，而不是摘要合并。
5. Learning Designer 能构建前置依赖、课程路线、章节故事线和目标。
6. Practice Designer 能生产可验证的实验和练习。
7. Reviewer 能发现事实、追溯、连贯性和实践方面的问题。
8. Publisher 能生成可阅读、可导航、可交互的网站。
9. 整条链具备任务状态、断点恢复、质量门禁和人工审批。
10. 至少使用一批新的资料完成一次端到端生产，证明不是只适用于现有知识库。

这里也有一个设计原则：知识质量优先于内容数量，完整工作流优先于批量生成。

5.1 Research Agent
支持以下输入：
- Markdown、TXT 等本地文件。
- PDF、论文。
- 网页和官方技术文档。
- GitHub 仓库。
- 已有知识笔记。
- AI 生成的研究报告。
- 用户提供的其他资料。
研究前必须先查询已有知识，回答：
1. 哪些知识已经存在？
2. 当前知识有哪些不足？
3. 新资料提供了哪些新增信息？
4. 是否与已有结论冲突？
5. 哪些内容值得进入知识体系？
研究报告必须记录研究范围、方法、来源、重要发现、证据、争议、局限、结论和未解决问题。
5.2 Evidence Analyst
复用：
- evidence/claim-ledger.json
- evidence/source-registry.json
要求：

- 不重复创建已有断言。
- 新断言默认 open。
- 不允许 AI 自行升级为 verified。

- 教材正文。
- 技术参考手册。
- 研究报告。
区分技术参考文档、系统教材、操作手册和面试知识库，不能混为同一种文体。
5.5 Learning Designer
设计符合人类认知过程的学习路线：

问题引入 → 前置知识 → 直观理解 → 概念建立 → 因果推导 → 数学和工程机制 → 实践验证 → 知识迁移 → 下一章承接。

每篇教材必须形成理解闭环，而不是告诉读者去看其他文档才知道核心原理。
5.6 Practice Designer
复用 tools/labs.json 和现有实验渲染体系。

让实践、实验、练习和 quiz 真正验证课程目标，而不是只在文档末尾增加一些问题。
5.7 Knowledge Reviewer
审核：
- 来源是否真实。
- 技术结论是否准确。
- 断言与正文是否匹配。
- 概念关系是否合理。
- 教材叙事是否连贯。
- 先修知识是否完整。
- 实践是否可操作。

ADR：
